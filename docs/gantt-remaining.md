# Гант: что осталось до полного паритета

Статус: 23.11.2026. Основной сценарий уже закрыт: ресурсы, story points, вехи,
прогресс, несколько базовых планов, FS-зависимости, критический путь, Agile-спринты,
Scrum-доска, производственный календарь и ёмкость спринта.

Задача на доске: **«Гант: остатки паритета»** (колонка «В работе», чек-лист).

## Сделано 23.11.2026

### Производственный календарь

- один календарь на проект;
- загрузка производственного календаря РФ из `isdayoff.ru`;
- праздники и сокращённые дни;
- рабочая неделя проекта;
- индивидуальная ставка сотрудника (`profiles.workday_hours`);
- ставка участника проекта (`project_members.workday_hours`) и норма проекта;
- фактические часы задачи: вручную или по проценту выполнения.

### Ёмкость спринта

- `gantt_sprints.capacity_hours`;
- Scrum-доска считает плановые часы задач;
- показывает «план X из Y ч»;
- предупреждает о перегрузке ёмкости, не блокируя сохранение.

## Осталось

### 1. Точная скорость с учётом архива и истории спринтов

Сейчас скорость считается по активным задачам в колонке «Готово». Задача, ушедшая
в архив, может потеряться.

Нужно:

- снимок спринта при завершении;
- учитывать архивные задачи, завершённые внутри спринта;
- считать carryover — что перенесено в следующий спринт;
- показывать скорость по последним 3–5 спринтам.

Данные:

- `gantt_sprint_snapshots` или поля `completed_at`, `completed_sprint_id`;
- не удалять `sprint_id` при архивации.

Критерии:

- завершённая задача из архива учитывается в скорости;
- перенесённая задача не считается выполненной дважды;
- средняя скорость не меняется от очистки активной доски.

Оценка: 0,5–1 день.

### 2. Отчёт «план / факт» по baseline

Сейчас baseline показывается призрачной полосой, но нет числового отчёта.

Нужно:

- таблица: baseline start/finish, текущие start/finish, отклонение в днях;
- перерасход часов: план против факта;
- сводка по проекту: сдвиг финиша, количество просроченных, суммарное отклонение;
- экспорт CSV/Excel;
- выбор baseline из существующего списка.

Критерии:

- задача сдвинулась на 3 дня — отчёт показывает +3;
- завершённая раньше срока показывает отрицательное отклонение;
- отчёт использует выбранный baseline;
- экспорт открывается в Excel.

Оценка: 1 день.

### 3. Зависимости SS/FF/SF и отрицательный lag

Сейчас поддерживается только Finish-to-Start и положительная задержка.

Нужно:

- типы связей FS, SS, FF, SF;
- lag/lead в днях, включая отрицательный;
- хранение типа и lag на уровне связи;
- пересчёт критического пути для всех типов;
- UI выбора типа и lag для каждой зависимости;
- отрицательный lag разрешён только руководителю.

Данные:

- `task_dependencies.relation_type`;
- `task_dependencies.lag_days`;
- текущий `tasks.dependency_lag_days` — fallback.

Критерии:

- SS: B начинается вместе с A;
- FF: B заканчивается вместе с A;
- отрицательный lag сокращает ожидание;
- критический путь корректен;
- циклы не ломают расчёт.

Оценка: 1 день.

## Порядок

1. Точная скорость и архивы.
2. Отчёт «план/факт».
3. SS/FF/SF и отрицательный lag.

## Решения заказчика

- календарь — один на проект;
- праздники — производственный календарь РФ;
- неполная ставка — на сотрудника и на проект;
- факт часов — по проценту выполнения с возможностью ручной правки;
- отрицательный lag — только руководителю.

## Не входит

- полноценный resource levelling;
- стоимость и бюджеты;
- зависимости между проектами;
- импорт MS Project.
