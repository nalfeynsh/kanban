# Функциональные флаги: анализ и план внедрения

Статус: **базовый механизм внедрён** (таблица `feature_flags`, админ-вкладка «Функции»,
скрытие модулей). Серверные проверки API и тарифы — следующий этап.

## Задача

Администратор должен включать и выключать крупные модули интерфейса:

- встречи / ВКС;
- чат;
- Гант;
- календарь;
- аналитику;
- проекты;
- файлы и вложения;
- уведомления.

Флаги нужны для двух сценариев:

1. **Разгрузка интерфейса.** Команде не нужны встречи или Гант — кнопки и разделы скрыты.
2. **Платные функции.** Модуль включается только на оплаченном тарифе.

## Модель данных

```sql
create table public.feature_flags (
  key text primary key,
  name text not null,
  description text,
  default_enabled boolean not null default true,
  min_plan text not null default 'free',
  dependencies text[] not null default '{}'
);

create table public.workspace_features (
  workspace_id uuid not null,
  feature_key text not null references public.feature_flags(key) on delete cascade,
  enabled boolean not null,
  updated_by uuid references public.profiles(id) on delete set null,
  updated_at timestamptz not null default now(),
  primary key (workspace_id, feature_key)
);
```

Для текущего одного рабочего пространства `workspace_id` можно заменить на `app_settings`-строку,
но таблица с ключом сразу готова к нескольким компаниям.

## Права

- читать флаги — все авторизованные;
- менять — только `admin`;
- проверять флаги на сервере — security-definer RPC `feature_enabled(key)`;
- UI скрывает кнопки, но **не является защитой**: серверные RPC/API проверяют флаг повторно.

## Зависимости

- `chat` не зависит от встреч.
- `meetings` требует `chat`? Нет; чат встречи можно отключить отдельно.
- `gantt` и `calendar` используют задачи, но не друг друга.
- `analytics` можно включать отдельно.
- `projects` — базовый модуль; его выключение скрывает выбор проектов, но не удаляет данные.

## Интерфейс

В «Команда → Доступ» добавить вкладку **«Функции»** (только админ):

- список модулей с переключателями;
- бейдж «Платно» для модулей выше текущего тарифа;
- предупреждение, если выключение модуля скрывает активные данные;
- подтверждение для выключения.

В шапке и навигации каждая кнопка проверяет флаг:

```js
const flags = useFeatureFlags();
{flags.meetings && <MeetingsButton />}
```

Маршруты `/meet/...`, `/calendar/...` и API дополнительно возвращают `404`/`403`,
если модуль выключен.

## Тарифы

`feature_flags.min_plan` + `workspaces.plan`:

- `free`: проекты, задачи, базовый канбан;
- `team`: чат, календарь, аналитика;
- `business`: встречи, Гант, файлы, расширенные интеграции.

При понижении тарифа флаги платных модулей выключаются автоматически, данные не удаляются.

## Этапы

1. Миграция `feature_flags` + `workspace_features`, сиды модулей.
2. RPC `feature_enabled` и админский `set_feature`.
3. Контекст/хук `useFeatureFlags`, скрытие кнопок и вкладок.
4. Серверные проверки для встреч, чата, Ганта, календаря и аналитики.
5. Админ-вкладка «Функции».
6. Привязка к тарифам и оплате (следующий этап).

## Риски

- выключенный модуль не должен ломать уже созданные данные;
- встречи и чат имеют собственные RLS-политики, их нужно проверить отдельно;
- флаги не заменяют RLS: скрытая кнопка не закрывает API;
- при нескольких workspace нужен `workspace_id` во всех запросах.
