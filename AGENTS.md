## 2. Требования заказчика (актуальный backlog)

Легенда: `[x]` сделано, `[~]` сделано в UI с требованием миграции БД, `[ ]` не начато.

### Баги

- [x] **Архив удалённых задач.** Заложен в ФТ, но фактически не работал: архив грузился без прав доступа, без автора, без нумерации. Переписано: модалка архива, фильтрация по правам, подпись постановщика, восстановление, «удалить навсегда».
- [x] **Не переносятся задачи между блоками.** Причина: на доске `SortableContext` содержал *колонки*, а `Column` использовал `useSortable` — при перетаскивании карточки колонки начинали «сортироваться», перехватывая цель. Пустая область колонки не была droppable-зоной, а `over.id` карточки из другой колонки не находился. Исправлено: колонка — `useDroppable` с `data.type='Column'`, кастомная collision detection (pointerWithin → задача, иначе колонка), пересчёт `position` для обеих колонок.
- [x] **Нет списка просмотра команды.** Добавлен блок «Команда» (кнопка в шапке) со списком сотрудников, ролями и переходом в профиль каждого.
- [x] **Данные профиля в модалке не сохраняются.** Причина 1: `ProfileModal` возвращал `null`, если `profile === null` — модалка физически не открывалась (совпадает с прод-багом из handoff). Причина 2: `update` без существующей строки `profiles` молча ничего не делал. Исправлено: модалка открывается всегда (поля из `session.user`), сохранение через `upsert`, явные ошибки, `refreshProfile` после записи.
- [x] **Локальный адрес в базе / конфиге.** `supabaseClient.js` берёт URL/ключ из `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` с fallback на текущий проект; `redirectTo` строится от `window.location.origin` (не localhost). В Supabase нужно обновить Site URL и Redirect URLs — см. §4.
- [x] **Удалённые задачи команды — по правам доступа.** Правило: архив показывает личные удалённые задачи, только если `created_by = я`; командные — всем, кто видит задачу в активном состоянии (RLS + дублирующая проверка на клиенте), с подписью постановщика.
- [x] **Вход через Яндекс не работает «молча».** Проверено внешними запросами: провайдер `custom:yandex` настроен, Supabase отдаёт корректный 302 на `oauth.yandex.ru` с `redirect_uri=https://…supabase.co/auth/v1/callback`, Яндекс показывает форму входа (callback принят). Значит ломается возврат. Теперь ошибки из URL (`?error_code=…&error_description=…`) разбираются и показываются, есть панель «Диагностика Яндекс-входа» с точным Redirect URI, требованиями к Site URL и готовым SQL для auth-триггера. Причина класса «Database error saving new user» закрывается новым `handle_new_user()` в миграции.
- [x] **Доступ и регистрация.** Закрытая регистрация по приглашениям: таблица `invites`, guard-триггер на `auth.users`, поле «код приглашения» на форме, RPC-проверка кода. См. §4.
- [x] **Дата создания vs срок.** В карточке и модалке выводится **срок** (`due_at`), а не дата создания. Дата создания — только справочно в архиве.
- [x] **Дата должна содержать время, а не только число.** Срок — `datetime-local`, отображение «11 ноя, 14:30»; просроченные — красным.
- [x] **Нумерация задач с датой.** У задачи стабильный номер `№ 14` (из `task_no` или вычисленный по `created_at`), в карточке — `№ 14 · 11 ноя, 14:30`, в архиве — `№ 14 · создана 11 ноя 2026`.

### Фичи

- [x] **Личная задача — человечек.** Замок заменён на иконку человека в цветном бейдже + подпись «Личная»; личные задачи видны только автору.
- [x] **Выделение команды в отдельный блок.** Кнопка «Команда» → список (аватары, роли, контакты, Telegram) → клик по сотруднику открывает его профиль.
- [x] **Telegram в профиле сотрудника.** Поле `telegram` (`@nick` или `t.me/...`) с нормализацией, предпросмотром ссылки и кнопкой «Открыть»; в карточке сотрудника — кнопка «Написать в Telegram» + копирование ника. Ссылка `https://t.me/nick` открывает чат (приложение или веб). До миграции ник хранится локально (см. §8).
- [x] **Роли и права (шаг 4 из handoff).** Панель «Доступ» (кнопка в шапке): список сотрудников с выдачей ролей, приглашения (создание/отзыв, статус «ожидает/использовано»), матрица прав «роль × право». Роли: `admin/manager/deputy/member`. Международная логика прав — `lib/permissions.js` (`can()`), сервер — `is_admin()`, политика `profiles_update_admin`, триггер `protect_profile_role`, политики `invites_*` (миграция 003).
- [x] **Матрица прав.** 12 прав: задачи (создание/редактирование/архив/исполнители/приоритет/управление чужими), команда, роли, приглашения, колонки. Матрица доступна всем (просмотр), управление — по правам роли.
- [x] **Логотип в шапке.** Прозрачный знак (`public/logo-mark.png`, белая подложка убрана из PNG), в тёмной теме подсвечивается фильтром. Клик по логотипу/названию всегда возвращает на главную: доска, сброс фильтров и выделения, закрытие всех модалок, скролл вверх.
- [x] **Перетягивание задач по рейтингу.** Задачи в колонке сортируются вручную (drag = рейтинг/порядок), `position` пересчитывается для всей колонки. Приоритет (Высокий/Средний/Низкий) — цветной индикатор.
- [x] **Стеклянный стиль и прозрачности.** Единая дизайн-система: анимированный градиентный фон, `backdrop-blur`, полупрозрачные панели, мягкие тени, стеклянные инпуты/кнопки, аккуратные скроллбары, светлая и тёмная темы.
- [x] **Диаграмма Ганта как в MS Project + выгрузка в файл.** Третий вид «Гант»: таблица задач (№, задача, исполнитель, начало, срок, дней) + таймлайн с месяцами, неделями и днями, подсветкой выходных и линией «сегодня»; масштабы Дни/Недели/Месяцы; полоса тянется (сдвиг сроков), правый край — длительность; сохранение в БД. Экспорт: **MS Project XML (MSPDI)**, **CSV/Excel**, **PDF через печать**. Код: `components/GanttView.jsx`, `lib/gantt.js`, `lib/export.js`.
- [x] **Массовое выделение задач (итерация 3).** Режим «Выделить»: чекбоксы на карточках, выделение колонки целиком, «Все», Esc — выход. Панель действий: перенос в колонку, назначение исполнителя, приоритет, «в архив». DnD в режиме выделения отключён — та самая причина, из-за которой фичу раньше откатили. Код: `components/BulkActions.jsx`.
- [x] **Внутренний чат: общий и личные (итерация 3).** Кнопка «Чат» в шапке с бейджем непрочитанных. Слева две группы: «Общий чат команды» (создаётся автоматически, видят все, у сообщений подпись автора) и «Личные» диалоги. Новый диалог — по кнопке «+» или «Начать диалог»: открывается отдельное окно «Кому написать» с поиском, список — только зарегистрированные активные пользователи (RPC `chat_candidates`). У каждого сообщения подписан автор: в общем чате «Вы» у своих и имя у остальных, в личном — имя собеседника. В списке сразу видны все зарегистрированные сотрудники без переписки — клик открывает личный диалог. Переписка с группировкой по дням, отправка по Enter (Shift+Enter — перенос строки), Realtime, отметка прочитанного, Telegram-ссылка и переход в профиль из шапки диалога. Код: `ChatModal.jsx` + `ChatView.jsx` + `lib/chat.js`; схема — миграции 004 (диалоги/сообщения), 005 (общий чат), 006 (список собеседников), 007 (все сотрудники сразу участники общего чата).

## 3. Правила разработки

1. Только функциональные компоненты + хуки, без классов.
2. Tailwind v4: `@import "tailwindcss"` + `@custom-variant dark`. Кастомные утилиты — в `index.css` (`glass`, `glass-panel`, `glass-input`, `glass-btn`, `app-bg`).
3. Не плодить зависимости: всё уже установлено.
4. Схема БД может отставать от кода → любое новое поле пишется только если оно есть в выборке (`lib/schema.js`), иначе запрос падает.
5. Ошибки Supabase всегда показываются пользователю, не только в консоль.
6. `key` для `TaskDetailModal` — по `id` задачи (иначе TipTap не пересоздаётся).
7. StrictMode не включать (двойные запросы).
8. Все пользовательские строки — на русском.
9. **Звуковое уведомление.** В конце каждого ответа (когда работа завершена и нужна проверка заказчика)
   запускать `tools/notify-done.cmd` — мягкие колокольчики `C:\Windows\Media\chimes.wav` (~1,6 с).
   Если заказчик просит другой звук — поменять файл в `.cmd` (`ding.wav`, `Windows Notify System Generic.wav`,
   `Alarm*.wav`). Скрипт `.ps1` в системе может блокироваться политикой выполнения — использовать `.cmd`.

## 4. Инструкция по окружению

### Supabase Auth
- Site URL: `https://kanban.layero.app/`
- Redirect URLs: `https://kanban.layero.app/`, `http://localhost:5173/`, `http://localhost:5173/**`
- Провайдеры: Email (Confirm email — вкл.), Custom OAuth `custom:yandex`.
- `localhost` в базе допустим только как dev-redirect; при смене домена обновлять оба поля.

### Layero
- Переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`.
- Сборка `npm run build` → `dist`, после изменения env — Redeploy.

### Миграции
- `001_kanban_upgrade.sql` — полный апгрейд: задачи, профили, invites, RLS, роли, auth-триггер.
- `002_telegram.sql` — минимальный скрипт только для `profiles.telegram`
  (если нужен лишь Telegram; полная миграция тоже добавляет эту колонку).
- `003_invites_policies.sql` — права на приглашения: менеджеры создают, админ отзывает/меняет.
- `004_chat.sql` — внутренний чат: `conversations`, `conversation_members`, `messages`,
  RPC `my_dialogs`, `get_or_create_dialog`, `mark_dialog_read`, RLS и Realtime-публикация.
- `005_team_chat.sql` — общий чат команды: флаг `conversations.is_team`,
  RPC `get_or_create_team_chat`, расширенный `my_dialogs` (is_team + число участников).
- `006_chat_candidates.sql` — RPC `chat_candidates()`: список только зарегистрированных
  пользователей для окна «Кому написать».
- `007_team_members.sql` — все зарегистрированные сотрудники сразу участники общего чата
  (корректный счётчик и доставка сообщений).
- `README.md` — пошаговая инструкция: New query → Run, проверочные SQL,
  типовые ошибки и порядок действий после миграции.

### Первый администратор
```sql
insert into public.invites (email, role, note)
values ('you@example.com', 'admin', 'bootstrap');
```
Затем зарегистрироваться с этим email. Дальше приглашения выдавать из SQL/админки.

### Что осталось сделать владельцу
1. Выдать себе роль: `update public.profiles set role='admin' where id = '<uuid>';`
2. Приглашение на свою почту (регистрация закрыта):

3. Authentication → URL Configuration: Site URL прод + `http://localhost:5173/**` в Redirect URLs

4. Применить `005_team_chat.sql` (общий чат команды) — без неё в чате будет только «Личные».

7. Задеплоить фронтенд: `git push` в `main` → Layero пересобирает.

### Яндекс-вход: что проверено 11.11.2026
- `GET /auth/v1/settings` → `external.email: true`, `disable_signup: false`, custom-провайдер не
  отображается в списке (это нормально).
- `GET /auth/v1/authorize?provider=custom:yandex&redirect_to=…` → **302** на
  `oauth.yandex.ru` с `client_id=01f1bf…` и `redirect_uri=https://theybeeteusxwxboczhe.supabase.co/auth/v1/callback`.
- Страница Яндекса по этой ссылке — форма входа (значит callback в приложении Яндекса принят).
- `GET /auth/v1/callback` без валидного state → 303 на `https://kanban.layero.app/` с
  `?error=invalid_request&error_code=bad_oauth_state` (Site URL = прод, ошибки приходят в URL).
- Вывод: клиент, провайдер и callback исправны; сбой происходит после возврата с Яндекса —
  чаще всего это auth-триггер создания профиля («Database error saving new user») либо
  несовпадение Redirect URL. Оба случая теперь видны в UI.

## 8. Известные ограничения / следующий шаг

1. **Приватность личных контактов** сейчас маскируется только в UI (`show_personal_data`).
   Через PostgREST строка профиля отдаётся целиком. Полная защита — отдельное
   представление `team_directory` с `null` для чужих личных полей и запрет прямого select.
2. **Код приглашения** — второй фактор, проверяется в RPC и в guard-триггере только по email.
   Полная проверка кода на сервере — через Auth Hook (before user created).
3. **Файлы** в бакете `task-files` публичные (Public URL). Для приватности — signed URL и RLS на Storage.
4. **Realtime** подключён только в чате (`messages`). Доска, задачи и профили не подписаны —
   их изменения видны после перезагрузки.
5. **История/аудит** удалений (`deleted_by`) фиксируется, но отдельной ленты событий нет.
6. **Гант:** нет зависимостей между задачами (стрелок-предшественников), вех и базового плана —
   следующий шаг, если нужно «совсем как MS Project». Перетаскивание сроков доступно
   только после миграции (`start_at` + `due_at`), иначе диаграмма работает в режиме просмотра.
7. **Telegram до миграции** живёт в `localStorage` браузера: владелец видит свой ник, но команда
   — только после применения `002_telegram.sql` (или `001`). В форме профиля об этом есть
   предупреждение и кнопка «SQL» для копирования нужного запроса.
8. **Массовые действия** пишут только те поля, что есть в схеме: перенос колонки и архив работают
   всегда, «исполнитель» и «приоритет» появятся после миграции (сейчас кнопки скрыты через `supports`).
